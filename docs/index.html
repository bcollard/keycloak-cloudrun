Keycloak on Cloud Run

Terraform and a container build for running Keycloak 26 on Google Cloud Run, behind a global external Application Load Balancer, with Cloud SQL for PostgreSQL.

Deploy Source on GitHub

Apache-2.0. Image published to ghcr.io/bcollard/keycloak-cloudrun, signed with cosign.

What you get

A production-shaped Keycloak with no VMs or Kubernetes cluster to run.

Serverless Keycloak

Cloud Run runs an optimized image (kc.sh start --optimized) with health, metrics and the PostgreSQL driver built in.

Private database

Cloud SQL for PostgreSQL on a private IP only, reached through a Serverless VPC Access connector.

Global load balancer

Static IP, TLS on 443, HTTP-to-HTTPS redirect, and a URL map that only exposes Keycloak's public paths.

Gated admin console

/admin is forwarded only when the request carries a shared-secret header. Cloud Run ingress blocks the *.run.app URL.

Signed image

GitHub Actions builds a multi-arch image, pushes it to GHCR and signs it with cosign. Cloud Run deploys it by digest through an Artifact Registry proxy.

Secrets in Secret Manager

Database and bootstrap admin passwords are stored in Secret Manager and injected as environment variables.

Architecture

How a request reaches Keycloak.

  1. DNS resolves the Keycloak hostname to a reserved global static IP.
  2. Port 443 terminates TLS with an uploaded wildcard certificate. Port 80 returns a 301 to HTTPS.
  3. The URL map sends /realms/, /.well-known/, /resources/ and /js/ to the backend. /admin needs the header. Everything else is redirected.
  4. The backend service reaches Cloud Run through a serverless NEG.
  5. Keycloak reaches Cloud SQL over the VPC Access connector.

Deploy

Requires a GCP project with billing, Terraform 1.10 or later, a GCS bucket for state, and private services access on the default VPC.

Configure

git clone https://github.com/bcollard/keycloak-cloudrun
cd keycloak-cloudrun
cp backend.hcl.example backend.hcl               # state bucket and prefix
cp terraform.tfvars.example values.auto.tfvars   # project, hostname, passwords

Issue the wildcard certificate

export DNS_ZONE_NAME=example.com GCP_PROJECT_DNS=my-dns-project \
       GCP_CREDENTIALS_FILE=/path/to/dns-sa.json ACME_EMAIL=me@example.com
make server-cert

Apply

make gcloud-login GCLOUD_CONFIG=my-config
make tfi
make tfp
make tfa

Point the hostname's A record at the forwarding_rule_ip_address output.

FAQ

Does CI deploy to Cloud Run?
No. GitHub Actions builds and signs the image when KEYCLOAK_VERSION changes. You run terraform apply yourself.
How do I upgrade Keycloak?
Bump KEYCLOAK_VERSION and push. When the build finishes, set keycloak_version and keycloak_image_digest (from make image-digest) and run make tfa.
Can the certificate be rotated without downtime?
Yes. The certificate uses name_prefix and create_before_destroy, so the proxy switches to the new one before the old one is deleted.
Why does the revision fail to start after changing features?
An optimized start needs the same --features list at build and run time. Keep the Dockerfile and cloudrun.tf values identical.
Does it support passkeys?
Yes, through Keycloak's WebAuthn passwordless policy. The README lists the realm settings.
